<p id="">TLDR: Authorizing actions on platforms like Solana sometimes requires calls to other programs, where addresses can be spoofed and exploited. With “badges” as a native first-class feature of Radix Engine v2 (REv2), this hack could never happen on Radix.&nbsp;&nbsp;</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1173px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1173px"><div id=""><img id="" src="/assets/62bb08493f13908a2a54ace5_xiMot9U3v_xkzk0Xsbhi8KdfChsnZZjZkzwlv8TK_Lk9ApOCMGhL1K8y83h9ZGLJjxGq2dTx_nqyLNO4y4N-wLdvGxwHw6keQoSmHkf0sVZL3T0NGaB2mPiu6T12xIOM9beZQ3j8L_GvTMjpMw.png" width="auto" height="auto" loading="auto"></div><figcaption id=""><a id="" href="https://twitter.com/RektHQ/status/1489269408405102596"><em id="">https://twitter.com/RektHQ/status/1489269408405102596</em></a></figcaption></figure><p id="">Wormhole is a bridge that allows users to deposit tokens on one network, such as ETH on Ethereum. A “wrapped” version of that token is then minted on Solana, whETH, which can be redeemed for the original ETH.<br></p><p id="">This allows representations of ETH to be utilized in Solana DeFi.&nbsp;</p><p id="">A set of nodes that are present on both networks, “Guardians”, monitor when ETH has been deposited into the Wormhole account.</p><p id="">Once deposited, the nodes sign a transaction to Wormhole on Solana. </p><p id="">The transaction includes a “sysvar address”, which tells Wormhole which account in the Solana System Program to use to verify the signatures in the transaction.&nbsp;</p><p id="">If the signatures are valid and meet the minimum threshold (e.g. 3/4) Wormhole mints the whETH. </p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1200px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1200px"><div id=""><img id="" src="/assets/62bb0de5241eb21e0b39f806_Wormhole-The-Solana-Way.png" width="auto" height="auto" loading="auto"></div></figure><p id="">On Feb 2 2022, after a few preparatory moves, a hacker submitted a transaction direct to Wormhole, ignoring the Guardians.</p><p id="">Instead of passing in the sysvar address for the legitimate System Program, the hacker passed in the address of their own program.&nbsp;&nbsp;</p><p id="">Part of the execution of this logic failed to check whether the submitted address was valid, and so execution was routed to the Hacker’s Program.</p><p id="">The hacker used this to mint 120k whETH, which they redeemed or traded for other tokens.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1200px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1200px"><div id=""><img id="" src="/assets/62bb0e0c3ece5636f545413e_Wormhole-The-Hack.png" width="auto" height="auto" loading="auto"></div></figure><p id="">So why couldn’t this hack happen on Radix’s upcoming Babylon mainnet?<br></p><p id="">Instead of authorizations being handled by system programs with specified addresses; on Radix, authorizations are handled by badges: a native first-class feature of the Radix Engine v2 execution environment.&nbsp;</p><p id="">In fact, there are 2 types of badge:</p><p id="">1. A badge is a resource, like an NFT or token, that can be presented (shown) to smart contract components in a tx. REv2 will only execute the tx if all required badges are presented for each requested action, as defined by the component.</p><p id="">2. A virtual badge exists temporarily for on-the-fly authorizations. Before tx execution, REv2 creates a virtual badge for each signer’s public key. When the tx then calls a component, REv2 will check whether the component requires any specific combination of badges.</p><p id="">Either of these options would work for an implementation of “Wormhole” on Radix. But the simpler of the two is the use of virtual badges.</p><p id="">Here, after 3 Guardians sign their tx, REv2 creates 3 virtual badges for each Guardian’s public key. REv2 then checks whether the virtual badges defined in the “Wormhole” component corresponded to those presented. As 3/4 were present, 1 whETH is minted for the user.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1200px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1200px"><div id=""><img id="" src="/assets/62bb0e49f8501870ef27f4ba_Wormhole-The-Radix-Way.png" width="auto" height="auto" loading="auto"></div></figure><p id="">Notice how there is no passing in of addresses to system programs.</p><p id="">Authorizations on Radix are handled natively by the platform through badges. As a result, the kind of complexity (and error) that led to this $326m hack just isn’t possible on Radix. </p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1200px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1200px"><div id=""><img id="" src="/assets/62bb0e8ab0d746e6779f91f1_Wormhole-The-Attempted-Hack.png" width="auto" height="auto" loading="auto"></div></figure><p id="">This is one more example where REv2 natively understanding what resources are means developers can create simple, elegant, powerful, and safe ways of managing what is devilishly complex on other platforms. That’s why we call it a DeFi Engine - the hard stuff is done for you.</p><p id=""><a id="" href="https://www.radixdlt.com/post/the-defi-engine-and-what-it-means-for-the-future-of-finance">https://www.radixdlt.com/post/the-defi-engine-and-what-it-means-for-the-future-of-finance</a></p><p id="">If you’d like to learn more about badges and virtual badges, our Scrypto v0.3 release blog provides a great overview:<br></p><p id=""><a id="" href="https://www.radixdlt.com/post/scrypto-v0-3-released">​​https://www.radixdlt.com/post/scrypto-v0-3-released</a></p><p id="">Thank you to Andrew Fraser <a id="" href="https://mobile.twitter.com/serfrae">@SerFrae</a>, CEO of <a id="" href="https://synchrony.fi/home">Synchrony Labs</a>, for insight on Solana architecture.</p><p id="">For the last in the Rekt Retweet series:</p><p id="">Rekt Retweet #9: The Transaction Manifest - Why the $14m Furucombo hack could NEVER happen on #Radix<br></p><p id=""><a id="" href="https://twitter.com/radixdlt/status/1539570728357462018">https://twitter.com/radixdlt/status/1539570728357462018</a></p><p id="">‍</p><p id="">‍</p>
