<p id="">RCnet v3 is now live.&nbsp; This is the last major test network release prior to the Babylon upgrade of mainnet!</p><p id="">As of this release, developers can build &amp; test with the knowledge that if it runs on RCnet v3, it’s going to run on Babylon.</p><h3 id=""><strong id="">What’s New?</strong></h3><p id="">As you might expect, not a whole lot has changed since RCnet v2 from a consumer perspective, as most of the stack has been focused on stabilization and small tweaks.</p><p id="">Naturally, there are new preview builds of the Radix Wallet, as well as RCnet v3-compatible versions for the host of associated developer tools:</p><p id="">→ <a id="" href="https://docs-babylon.radixdlt.com/main/getting-started-developers/wallet/wallet-and-connector-installation.html">Installing the Radix Wallet Preview &amp; Connector Extension<br></a>→ <a id="" href="https://www.npmjs.com/package/@radixdlt/radix-dapp-toolkit/v/0.6.1">Radix dApp Toolkit<br></a>→ <a id="" href="https://github.com/radixdlt/radix-engine-toolkit">Radix Engine Toolkit<br></a>→ <a id="" href="https://radix-rcnet-v3-gateway.redoc.ly">Gateway API<br></a>→ <a id="" href="https://rcnet-v3-dashboard.radixdlt.com">Dashboard</a></p><h3 id=""><strong id="">Anything for Scrypto Developers?</strong></h3><p id="">While Scrypto has been feature-complete since RCnet v2, the team has been paying close attention to community feedback, and the big news to announce is that an entire new <a href="https://docs-babylon.radixdlt.com/main/scrypto/testing/scrypto-test.html">unit testing framework</a> has been developed and rolled out.&nbsp;The new framework enables much more rapid creation of tests which don’t wish to concern themselves with describing an entire transaction, allowing developers to write narrowly targeted test scenarios and easily set up the appropriate pre- and post-conditions.&nbsp; For integration-level testing, the existing test runner framework is, of course, still present.</p><p id="">Decimal-related types for fixed precision math have also gotten an overhaul in response to feedback, both to support more real-world scenarios with the built-in types and to ensure that the compiler can enforce proper handling of potential overflow scenarios.</p><p id="">While some RCnet v2 applications will transition straight to RCnet v3 without any updates, there have been many small adjustments; please see the <a href="https://docs-babylon.radixdlt.com/main/scrypto/release_notes/migrating_from_0.11_to_0.12.html">release notes</a> for the full details.</p><h3 id=""><strong id="">RCnet v3 Q&amp;A</strong></h3><p id=""><strong id=""><em id="">Does RCnet v3 have “real” tokens and applications on it that will become part of mainnet?</em></strong></p><p id="">No, it is strictly a test network, and everything on it will eventually vanish.</p><p id=""><strong id=""><em id="">Will there be additional test releases prior to Babylon go-live?</em></strong></p><p id="">While there may be another interim release or two with under-the-hood changes to RCnet v3, there won’t be another major release.</p><p id=""><strong id=""><em id="">Is more data coming about the Olympia to Babylon migration?</em></strong></p><p id="">There are currently two blogs around this subject:</p><p id=""><a id="" href="https://www.radixdlt.com/blog/babylon-automatic-migration-guide">Babylon Automatic Migration Guide<br></a><a id="" href="https://www.radixdlt.com/blog/final-olympia-protocol-update-released">Final Olympia Protocol Update Released</a></p><p id="">Closer to the switchover, you can expect another article which goes into some more detail about what happens on the big day.</p><p id=""><strong id=""><em id="">Will there be a long-running Stokenet test network for Babylon?</em></strong></p><p id="">Yes, a Babylon Stokenet will be spun up around the time of Babylon go-live.&nbsp; It is expected to be a fresh network, without any state from the Olympia-based Stokenet.</p><p id=""><strong id=""><em id="">I’m preparing an application for release with Babylon, where can I get my questions answered?</em></strong></p><p id="">Best place to ask is always in the <a id="" href="https://discord.com/channels/417762285172555786/765994894749597697">Scrypto channel</a> on Discord!</p><p id="">‍</p>
