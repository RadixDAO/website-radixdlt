<p id="">We’re pleased to announce that <strong id="">Radix Alexandria has launched today</strong>!</p><p id="">The focus of Alexandria is developers – and that means the first release of Scrypto and <a id="" href="https://www.radixdlt.com/post/radix-engine-v2-an-asset-oriented-smart-contract-environment">Radix Engine v2</a> offering a new <a id="" href="https://www.radixdlt.com/post/scrypto-an-asset-oriented-smart-contract-language">asset-oriented way of building smart contracts</a> that <a id="" href="https://www.radixdlt.com/post/the-problem-with-smart-contracts-today">addresses the failings of smart contracts today</a>.</p><p id="">If you’re a developer and want to dive straight in, <a id="" href="https://developers.radixdlt.com">head over to our new Radix Developers Site</a> – and then contribute your creations on our new <a id="" href="https://developers.radixdlt.com/ecosystem">Radix DeFi Ecosystem</a> page.</p><p id="">If you want to learn more about why Scrypto and Radix Engine v2 are so important to bring DeFi into the mainstream, read our freshly updated <a id="" href="https://www.radixdlt.com/whitepapers/defi">DeFi White Paper</a>.</p><p id="">Let’s take a look at what’s available today.</p><h3 id=""><strong id="">What is Alexandria?</strong></h3><p id="">Followers of Radix know that we have a <a id="" href="https://learn.radixdlt.com/article/what-is-the-radix-roadmap">sequence of planned technology releases</a>: <strong id="">Olympia → Alexandria → Babylon → Xi’an</strong> and beyond.</p><p id="">Radix Olympia marked the launch of the Radix public network “mainnet”.</p><p id="">Alexandria, however, is a little different; it is not a mainnet update. Instead, Alexandria delivers the first release of a new smart contract development experience with Scrypto and Radix Engine v2. Developers can now use a set of Scrypto tools on their own computer to start experimenting with what it’s like to build and run DeFi dApps using Scrypto – for now without deploying code to a network.</p><p id="">Babylon is where we bring Olympia and Alexandria together, with a substantial update to mainnet to make it possible to deploy Scrypto code to the network – in short, bringing DeFi capability to Radix.</p><p id=""><strong id="">Developers can think of Alexandria as “early access” – their chance to become Scrypto experts, help shape the development of Scrypto with their feedback, and get their own DeFi dApps ready to go to be the very first deployed to Radix at the Babylon release.</strong></p><p id="">We’re super excited to get it into developers’ hands starting today.</p><h3 id=""><strong id="">What is included with Alexandria for developers?</strong></h3><p id="">Alexandria brings the release of an early form of Scrypto and associated tools on the <a id="" href="https://github.com/radixdlt/radixdlt-scrypto">Scrypto Github repo</a> – all open source. Scrypto itself is essentially a set of libraries and extensions to the popular Rust programming language that (when run within the Radix Engine environment) provide the asset-oriented features that define the Scrypto experience of writing smart contracts – or, as we call them, <em id="">blueprints</em> and <em id="">components</em>.</p><p id="">But the Scrypto language and compiler alone aren’t enough to really start building. Scrypto components are intended to be run within a shared network environment where they can be used via transactions and interact with accounts, resources, and even other components. So to meaningfully develop and test Scrypto blueprints and components, the developer needs some way of “deploying” that code and interacting with it.</p><p id="">Alexandria provides a simulator of such an environment that developers can use to quickly build, test, and iterate Scrypto code – all on their local computer. This includes the ability to deploy Scrypto code to a simulated “ledger” that uses your local filesystem, and a simulated Radix Engine to run (and validate) Scrypto code as if it were running on a network. Alexandria also includes tools to push simulated transactions through Scrypto components, as well as make it convenient to do things like create accounts and resources (ie. tokens, NFTs, and badges).</p><p id="">All of this is included in the Scrypto Github repo for developers to start working with. To get a bit more technical, that repo includes:</p><ul id=""><li id=""><strong id="">A Rust cargo file for Scrypto</strong>, including the libraries that provide Scrypto’s syntax and data types, and the Scrypto extension to the Rust compiler</li><li id=""><strong id="">Command line tools for development</strong>, including <strong id=""><em id="">resim</em></strong> – providing commands to interact with the local Radix Engine simulator and filesystem-based ledger – and <strong id=""><em id="">scrypto</em></strong> – a convenience wrapper for cargo to do Scrypto-specific things</li><li id=""><strong id="">Early Scrypto documentation</strong>, including a getting-started tutorial on Scrypto basic concepts, Scrypto code examples, language reference, and more</li></ul><p id="">Beyond simply having a look at Scrypto syntax, these tools let a developer actually begin building and testing real DeFi functionality – and do so right away while Scrypto continues to improve and evolve as we work toward on-network Scrypto at Babylon. We expect that any code developed with these tools now with Alexandria will be deployable to mainnet with little-to-no changes at Babylon.</p><h3 id=""><strong id="">How can developers get started with Scrypto?</strong></h3><p id="">First, our new <a id="" href="http://developers.radixdlt.com">Radix Developers Site</a> is the Radix hub for information on Scrypto and all the links you need to installation instructions, documentation, examples, and more.</p><p id="">You might also want to check out our series of blog articles describing the need for Scrypto, how it’s different from today’s smart contract paradigm, and the asset-oriented concepts it uses.
