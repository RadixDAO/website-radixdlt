<h3 id="">Building on the Ledger Nano S</h3><p id="">At Radix we’re developing the next generation distributed ledger technology. We want to provide people with secure ways to store their <a id="" href="http://eXRD Tokens are Live(Opens in a new browser tab)">Radix coins</a>, and there's nothing quite as secure as using a hardware cryptocurrency wallet, also known as a cold wallet.In this post I'll describe what cold wallets are exactly and how they work, as well as go into detail about how to set up the build environment for the Ledger Nano S, compile a Hello World application and deploy it to the Nano S. </p><p id="">I decided to write this as I ran into some trouble with the official guide provided by Ledger.</p><h3 id="">What is a cold wallet?</h3><p id="">A cold wallet is a method of storing private keys that isn't connected to the internet. This prevents attackers, no matter how clever, from stealing your private keys unless they gain physical access to the cold wallet device.The simplest way of going about this is writing down your private keys on a piece of paper. </p><p id="">This approach has some obvious drawbacks, such as that anyone who can take a picture of that piece of paper has access to your wallet, as well as some more subtle problems - whenever you want to make a transfer, you will need to input the key into an internet connected device, at which point you’re open to all of the same attack vectors as if you had just stored the key on the computer the whole time.There is a way around the problem - you could have a USB device that stores your private keys. </p><p id="">When you want to make a transaction, you connect it to your computer, create the transaction and send it to your hardware wallet to sign with your private key. The wallet then returns a signed transaction. But your private keys have never left the wallet. So even if an attacker has fully compromised your computer, your private keys are safe. <a id="" href="https://cointelegraph.com/news/newly-discovered-vulnerability-in-all-ledger-hardware-wallets-puts-user-funds-at-risk" target="_blank">They aren't bulletproof</a> however it’s about as secure as you can get nowadays.The three main companies that make this type of hardware wallet are <a id="" href="https://www.ledgerwallet.com/">Ledger</a>, <a id="" href="https://trezor.io/">Trezor</a> and <a id="" href="https://www.keepkey.com/">KeepKey</a>. We chose Ledger Nano S to start with.</p><h3 id="">How it works</h3><p id="">When you first start up a Nano Ledger S an interesting thing happens - you are asked to note down a list of random 24 words. This mnemonic is your master key. It maps to a 256 bit long number but it's a lot easier to note down and potentially remember a 24 word mnemonic than a list of 256 ones and zeroes.Your master key is one of 2256.possible keys. That is one of 115 792 089 237 316 195 423 570 985 008 687 907 853 269 984 665 640 564 039 457 584 007 913 129 639 936 possible mnemonic seeds. </p><p id="">For comparison, there are an estimated 2223 atoms in the Milky Way. Somebody getting the same key as you is orders of magnitude less likely than somebody randomly picking an atom in your left toe from all the atoms in the galaxy.The Ledger S uses what is known as <em id="">Hierarchical Deterministic Key Generation</em>. This means that it can derive a virtually infinite number of private-public key pairs from a single starting point - the master key. </p><p id="">And because the process is deterministic, it will yield the same keys even when you import the same master key on a new Nano S, or even any other hardware or software wallet that implements the same key generation scheme.To avoid clashes between different applications, the developers of different cryptocurrencies have gotten together and reserved a space on the tree for each coin. Bitcoin lives at index 0, index 1 is reserved for testnets of all coins, 2 is Litecoin and interestingly Dogecoin is at index 3. </p><p id="">You can see the full list <a id="" href="https://github.com/satoshilabs/slips/blob/master/slip-0044.md">here</a>.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-center" data-rt-type="image" data-rt-align="center" data-rt-max-width=""><div id=""><img id="" alt="Hierarchicale Deterministic Tree" src="/assets/6087c8762148c1f0cce33ad1_5a848571bf55410001f0abf9_hd_keygen.png" width="auto" height="auto" loading="auto"></div><figcaption id="">‍Source: <a id="" href="https://ledger.readthedocs.io/en/latest/background/hd_use_cases.html" target="_blank">https://ledger.readthedocs.io/en/latest/background/hd_use_cases.html</a></figcaption></figure><p id="">All of this means that you have a virtually infinite number of private/public key pairs for any cryptocurrency you want to hold in the wallet, all derived from the single master key.</p><h3 id="">How to get started developing for the Ledger Nano S</h3><p id="">I ran into some difficulties setting up the build environment for Ledger hardware wallets following the guides provided by Ledger, so I have compiled my own guide with steps that worked for me. I use OS X, but this guide should work on any operating system, since we’re using Docker.</p><h3 id="">Things you will need to get started</h3><p id="">These are the tools required for building and deploying applications for the Nano S. Follow the respective installation guides for your operating system:</p><ul id=""> 	<li id="">Docker <a id="" href="https://docs.docker.com/engine/installation/" target="_blank">https://docs.docker.com/engine/installation/</a></li> 	<li id="">Python 2.7.* <a id="" href="https://www.python.org/downloads/" target="_blank">https://www.python.org/downloads/</a></li> 	<li id="">Virtualenv <a id="" href="https://virtualenv.pypa.io/en/stable/installation/" target="_blank">https://virtualenv.pypa.io/en/stable/installation/</a></li></ul><h3 id="">Setting up the build environment</h3><p id="">The easiest way to get started with making your own custom apps for the Nano S is using Docker.In this guide we will build and deploy the <strong id="">blue-app-helloworld</strong> found at <a id="" href="https://github.com/LedgerHQ/blue-sample-apps/tree/master/blue-app-helloworld">https://github.com/LedgerHQ/blue-sample-apps/tree/master/blue-app-helloworld</a>. Clone the repository wherever you would like, I have mine under <strong id="">/Users/edgarsnemse/Documents/Dev/blue-sample-apps</strong>The first step is to pull the Docker image we will be using to build the application.docker pull nbasim/ledger-blue-sdkAfterwards you can run the docker image. We need to make the source directory accessible within the docker container. </p><p id="">This can be achieved using the <strong id="">--mount</strong> flag. It can take a number of arguments, all of which can be seen <a id="" href="https://docs.docker.com/storage/bind-mounts/">here</a>, but in our case we only care about 3 of them <strong id="">- type=bind</strong>, <strong id="">source=[path on the host OS]</strong> and <strong id="">target=[path inside the container]</strong>.docker run -t -i --mount type=bind,source=/Users/edgarsnemse/Documents/Dev/blue-sample-apps,target=/home/dev nbasim/ledger-blue-sdk /bin/bash<br><br>apt-get update<br><br>apt-get install libc6-dev-i386cd<br><br>/home/dev/blue-sample-apps/blue-app-helloworldmake BOLOS_ENV=/opt/ledger-blue/ BOLOS_SDK=/home/dev/BOLOS_SDK<br><br>This will create an app.hex file in the blue-app-helloworld/bin directory. This is the binary of your application which you can now install and run on your Nano S.</p><h3 id="">Installing the application on the device</h3><p id="">Ledger provides a Python-based tool to install compiled binaries to their devices. It can do <a id="" href="http://ledger.readthedocs.io/projects/blue-loader-python/en/latest/">a lot more</a> but for now we’re only interested in the application deployment tools.First you need to install the pip package. It is recommend installing it in a virtualenv to avoid any dependency versioning issues.virtualenv ledger<br><br>source ledger/bin/activate<br><br>pip install ledgerblueYou can then use the following command from the bin directory containing the app.hex file to deploy your application to the Nano S.python -m ledgerblue.loadApp --targetId 0x31100002 --apdu --fileName app.hex --appName Hello --appFlags 0x00You should now see the <strong id="">Hello</strong> application listed in the &nbsp;app menu on the Nano S.</p><h3 id="">Uninstalling</h3><p id="">To remove the appliocation from the device use this command.python -m ledgerblue.deleteApp --targetId 0x31100002 --appName Hello</p><h3 id="">Conclusion and next steps</h3><p id="">At this point you are ready to start developing your applications. If you want to read more about how the Nano S works, Ledger provide a very detailed document <a id="" href="http://ledger.readthedocs.io/en/latest/background/master_seed.html">here</a>. If you are considering building on the Ledger Nano S, you can find the full documentation <a id="" href="https://ledger.readthedocs.io/en/0/bolos/index.html">here</a>.</p>
