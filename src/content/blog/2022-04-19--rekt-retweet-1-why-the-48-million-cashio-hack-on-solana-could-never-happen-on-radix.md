<p id="">TLDR: Tokens on Solana rely on validations implemented by smart contract developers. If they make one mistake, the tokens are gone. Tokens on Radix are validated by the platform itself. If you’re a developer on Radix, you can’t even make the kind of mistake that led to this hack.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1170px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1170px"><div id=""><img id="" src="/assets/625e7c2435567656330a625d_Screenshot-2022-04-19-at-5.08.16-PM.png" width="auto" height="auto" loading="auto"></div><figcaption id=""><a id="" href="https://twitter.com/RektHQ/status/1506634547705913352">https://twitter.com/RektHQ/status/1506634547705913352</a></figcaption></figure><p id="">On March 23 the smart contract for the Cashio stablecoin dApp was exploited for $48 million, due to an error in the smart contract’s “asset validation” logic. This type of exploit isn’t possible on Radix as the validation is handled by the Radix platform, not the smart contract.</p><p id="">Cashio is a dApp that allows users to mint a US dollar stablecoin, $CASH, by transferring Saber LP Tokens to Cashio’s LP token account. The LP token collateral backs the value of the stablecoin.</p><p id="">The Cashio smart contract monitors its Saber LP token balances, and if the deposited tokens pass the Cashio smart contract’s validation rules, Cashio mints an equivalent amount of $CASH for the user.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1600px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1600px"><div id=""><img id="" src="/assets/625e7989b8029b14e305b910_K5NuCid7gQh8zWqoacDRQl4f2KaGKtxUPD9j9WcVr5zZ5kzul9ab2nuMRDTqylTmTHPld69IKUuO5lG_06JhaD-3k65noOleNXos9vChEgzeC9IgL4HIgIyk_O2uG2rVtWa5xZZx.png" width="auto" height="auto" loading="auto"></div></figure><p id="">However, on March 23 2022, a hacker was able to create a fake contract with fake LP balances, and trick the Cashio smart contract into believing that a deposit of 27m fake LP tokens meant that it should mint 2Bn $CASH for the hacker. That 2Bn in $CASH was then sold for $48m.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1600px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1600px"><div id=""><img id="" src="/assets/625e7a2fe5c6e0b3c04b760a_oRZ5DnO_2OzVk5bFaBOFzuckiUTqCwD58t55AUJ2e-rjFM8BQb_0lsyiqEFFvyMTnpqc4PrUELIQtLhv83S8kW7jywQ8bkBDH5gg18zOmLuyt95TWrZqeQac8uNqUR9cW_G7PwKD.png" width="auto" height="auto" loading="auto"></div></figure><p id="">The Cashio smart contract missed a small but vital step in the process of checking whether the deposited tokens were correct. Because developing tokens and smart contracts today is complex and unintuitive, these types of error are easy to make.</p><p id="">The root cause is that all tokens on Solana, and the validations that go with it, are the sole responsibility of the smart contract developer. Solana doesn’t provide any protections. If there’s a single mistake in the developer’s “asset validation” logic, a hacker could exploit it.</p><p id="">So why couldn’t this hack happen on Radix’s upcoming Babylon mainnet with smart contract capability?</p><p id="">The answer is that tokens are a native feature of Radix, and Radix has an in-built “DeFi Engine” that handles all the core validations. We call it Radix Engine.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1600px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1600px"><div id=""><img id="" src="/assets/625e7a5cb8029b6c82065f31_FolF7fNoUOMQkPhxlpDrtbItsKrFRIJ9mU82UTo9fefDH_5IDjGti36d8jK48yJoFLcmeoOotaeLnYWJS3ka9_KUicRD9Y0x_sROe4JL_ZTwiAqGkDHMRamsWKnGGrCbasumipRl.png" width="auto" height="auto" loading="auto"></div></figure><p id="">With this in place, DeFi developers on Radix don’t have to worry about designing their own “asset validation” logic, because Radix Engine ensures only the correct token can be put into a vault intended for that token. It’s simply not possible to deposit a different faked version of a token into the vault.&nbsp;</p><p id="">Going back to the example, if a hacker on Radix tried creating a fake LP token, Radix Engine would just reject the transaction, because the dApp doesn’t have a vault for the fake token.</p><figure id="" class="w-richtext-figure-type-image w-richtext-align-fullwidth" style="max-width:1600px" data-rt-type="image" data-rt-align="fullwidth" data-rt-max-width="1600px"><div id=""><img id="" src="/assets/625e7a62abc16195559ae8b5_cwFmYN5S74dxUN9eDeaePMhPzFpmmkTwuCLPGBaj2ytr_G6rs3K3t2fL4j82HPZswxq0Ga6yqpdv0qp7eHteIlfUSdNydiCo2drN82GFKAAwyzijcCLtN0BRhpJ5mc-0Z2p6-9iX.png" width="auto" height="auto" loading="auto"></div></figure><p id="">Not only does this make smart contracts on Radix way more secure, but it also saves developers tons of time, as they no longer have to worry about programming all those validations themselves.</p><p id="">If you’d like to learn more about why Radix’s DeFi programming language Scrypto makes developing on Radix secure and intuitive, and how Radix Engine would prevent these kind of hacks, visit <a id="" href="https://go.radixdlt.com/rekt-retweet-1">https://go.radixdlt.com/rekt-retweet-1.<br> </a></p><p id=""><strong id="">By Ben Fargher - RDX Works </strong></p>
