<p id="">Following the release of the<a id="" href="https://www.radixdlt.com/blog/2026-strategy-the-next-chapter-of-radix"> 2026 Strategy</a>, we set a clear direction: a Radix network that is self-sustaining, resilient, and fully decentralized.</p><p id="">Since the restructure in early 2025, the Radix Foundation or subsidiaries have maintained a wide range of operational services. These range from critical infrastructure like the Babylon Gateway services, through to “nice to have” items like the “<a id="" href="https://gumball-club.radixdlt.com/">Gumball club</a>” demo dApp.&nbsp;</p><p id="">In line with the 2026 Strategy, we are initiating the transition of these functions. We are moving from a model where the Foundation provides and maintains these services, to one where the community and partners operate them.</p><p id="">To drive this discussion, we are publishing this overview of systems and services currently run by the Foundation. It is an invitation for developers, node runners, and businesses to identify where they can step in, take ownership, and potentially commercialize these essential services.</p><h2 id="">Foundation Technical Operations</h2><p id="">We have categorized our current infrastructure and services into three pillars based on network criticality.&nbsp;</p><p id=""><em id="">Note, this is not an exhaustive list and is intended as a high level technical overview. It does not include business functions such as Market Making, Grants, Validator Subsidies, Treasury Management, or similar activities.</em></p><h3 id="">P1 - Core Network Access &amp; Resilience</h3><p id="">These are high-availability services. If they stop, users cannot easily interact with the ledger or dApps via standard methods.</p><ol id=""><li id="">Babylon Gateway Endpoint: The primary API that indexes the ledger and enables transaction submission via the wallet. It’s default for the Radix Wallet, Dashboard, and many dApps.</li><li id="">Radix Connect Relay: The signaling service that enables the Radix Wallet to connect securely to dApps running in mobile browsers.</li><li id="">Signaling Server: This is the service that enables the Radix Wallet to establish a P2P connection with the Chrome Desktop extension.</li></ol><p id="">We need independent, commercial-grade providers to run these endpoints so the network has no single point of failure.</p><p id="">‍</p><h3 id="">P2 - High-use &amp; Product Maintenance</h3><p id="">These are stable tools and platforms. They do not require constant "hosting" to keep the network alive, but they require active maintenance, code governance, and app store management.</p><ol id=""><li id="">Radix Node Software: The core protocol code run by validators. While open source, the release cycle and governance need a community-led home.</li><li id="">Core Code Repos: These are already mostly open sourced, and include Gateway, Scrypto, Radix Engine Toolkit (and supporting libraries), ROLA, and others. Currently the main Github Repos for these are maintained and updates merged by the Foundation/subsidiaries.&nbsp;&nbsp;</li><li id="">Radix Wallet (iOS/Android): Currently published for both iOS and Android, these apps are currently the main way many users interact with the Radix network. The apps are listed on the App Stores by Radix Publishing. The code for the wallet is open source, and we’re working to make it easier for others to launch their own wallets.&nbsp;</li><li id="">Radix Connector Extension (Chrome): A Chrome extension that enables desktop pages to send transactions to the Radix mobile wallet for signing. It is also essential for using Ledger devices with Radix Wallets.</li><li id="">Turn Server: This is a fallback service if the Desktop&lt;&gt;Mobile peer-to-peer connection cannot be established.&nbsp;</li><li id="">Radix Ledger App: The official application in Ledger Live to interact with the Radix network using a Ledger hardware wallet.</li><li id=""><a id="" href="http://radixdlt.com">radixdlt.com</a>: The main website and URL for the Radix Network. Currently hosted on Webflow. Includes the Radix blog.</li><li id="">Radix Social &amp; Community channels: X, Reddit, Meta, Telegram, Discord, and others.&nbsp;</li></ol><p>‍</p><h3 id="">P3 - Non-Critical but Maintained</h3><p id="">These items improve the developer and user experience. They are currently maintained by the Foundation/subsidiaries but represent prime opportunities for community teams to take over or build superior alternatives.</p><p id="">User Service &amp; Demos</p><ol id=""><li id="">Asset service: Simple service that presents foundation managed assets such as icons for foundation managed Dapp and tokens</li><li id="">Image Service: Image service that provides compression and caching on Cloudflare for community and foundation image assets.</li><li id="">Token Price and NFT Price Service: this service uses a third party API to populate the token/NFT prices in the Radix Wallet both overall, and per account.</li><li id="">Dashboard: This is a page that indexes Radix transactions and history for users. It also enables a UX for interacting with network staking. Community alternatives, such as <a id="" href="https://www.radxplorer.com/">Radxplorer</a> already exist.</li><li id="">RadQuest: This is a guided onboarding dApp for Radix users. Both the front-end and essential backend/on-chain services are maintained by the Foundation.</li><li id="">Gumball Club: This is a very simple demo application that users can interact with when onboarding with the Radix wallet.</li><li id="">IDOS Proof-of-Personhood: A small dApp that integrates with the IDOS system to issue badges on Radix.</li><li id=""><a id="" href="http://wallet.radixdlt.com">wallet.radixdlt.com</a>: A simple front-end that guides the install and setup of the Radix Wallet.</li><li id="">Radix Rewards: A front-end and back-end system that monitors on-chain activity and issues reward points.&nbsp;</li><li id="">Radix Consultation dApp: A front-end and back-end system that enables admins to submit proposals for token holders to input on.&nbsp;</li></ol><p id="">‍</p><p id="">Developer Tooling:</p><ol id=""><li id="">Radix dApp Toolkit: A github repo that handles the wallet&lt;&gt;dapp interactions and connect button.</li><li id="">Dev Console: This is an app to assist developers when interacting with the Radix network.</li><li id="">Sandbox: An app that assists developers when interacting with the Radix network.</li><li id="">Arculus CSDK: This is a private repo that is required to build a new release of the Radix Wallet that can support the Arculus card.</li><li id=""><a id="" href="http://docs.radixdlt.com">Docs.radixdlt.com</a>: Develop documentation for Radix</li><li id=""><a id="" href="http://academy.radixdlt.com">academy.radixdlt.com</a>: An educational course that guides learning Scrypto basics. Live but not maintained.</li><li id=""><a id="" href="http://learn.radixdlt.com">learn.radixdlt.com</a>: A knowledge-base directed to non-technical users to learn about Radix. Currently hosted on Webflow.</li><li id="">Fullstack Dapp Example: An example dApp for developers</li></ol><p id="">‍</p><p id="">Miscellaneous:</p><ol id=""><li id="">XRD Supply API: this is a simple API that provides supply details for CoinGecko</li><li id="">dApp Catalog Service: This is a simple service that is used to populate the dApp directory in the Radix Walet.</li><li id="">Olympia-explorer: A legacy network explorer for the Olympia Radix Network.&nbsp;</li><li id="">Foundation Validators: Two validator nodes operated by the Radix Foundation for network monitoring and participation.&nbsp;</li><li id="">Olympia Radix Wallet: An old desktop wallet that can be used for updating to Babylon. End-of-life and no longer maintained.</li></ol><ol id="" start="11"><li id="">Stokenet Gateway and Stokenet nodes: Run the Radix testnet.</li></ol><p id="">‍</p><h2 id="">Next Steps</h2><p id="">The Foundation is committed to a responsible handover. We will not "switch off" critical services without a transition plan. We will continue to maintain P1 and P2 items while we work with the community to establish alternative arrangements.</p><p id="">This initial overview is to provide the Radix Community a map of major services to consider submitting proposals or responding to RFPs for these services, or other alternatives.&nbsp;</p><p id="">We are currently finalizing the technical requirements for the P1 items, such as defining traffic load and service level expectations, which we will then share.&nbsp;</p><p id="">Once ready, we will open a Request for Proposals (RFP) process for these items. We are looking for professional operators who can run these services with the same (or better) reliability than the Foundation.</p><p id="">From there, if the community has not already progressed proposals, we will continue that process for the P2s.&nbsp;</p><p id="">Although we will be releasing formal RFPs, this is an open invitation to collaborate immediately.</p><p id="">If your team has the capability to run high-uptime infrastructure, or the passion to maintain core developer libraries or marketing platforms, or a business looking to enter the Radix stack, now is the time to begin advocating for this within the community and we welcome proposals for any of the above ahead of formal RFPs.</p><p>Most of the community proposals are currently being posted on&nbsp;<a href="https://radixtalk.com/c/governance/radix-community-dao/52">RadixTalk</a>.</p>
