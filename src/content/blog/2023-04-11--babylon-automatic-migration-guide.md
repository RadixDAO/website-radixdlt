<blockquote id=""><strong id="">TL;DR: Users of the Radix Wallet or a Ledger hardware wallet do not need to do anything to be ready for the Babylon migration.&nbsp; All tokens &amp; stake positions will automatically be carried over.</strong></blockquote><p id="">At Babylon launch, the Radix Public Network will undergo a permanent upgrade to <a id="" href="https://www.radixdlt.com/blog/scrypto-an-asset-oriented-smart-contract-language">enable programmability</a>, <a id="" href="https://www.radixdlt.com/blog/radix-engine-v2-an-asset-oriented-smart-contract-environment">a new execution engine</a>, <a id="" href="https://docs-babylon.radixdlt.com/main/scrypto/transaction-manifest/intro.html">a new transaction model</a>, and <a id="" href="https://docs-babylon.radixdlt.com/main/scrypto/resources/introduction.html">more powerful native assets</a>.&nbsp; <strong id="">All existing assets, stake, and accounts will automatically be migrated, and there will be an easy way to transition from the current Radix Desktop Wallet to the new Babylon Radix Wallet for iOS and Android.&nbsp; All interfaces to the network and the Gateway will be different after the upgrade, so any applications written to work only on Olympia will stop working.</strong></p><p id="">‍</p><h2 id=""><strong id="">Mechanics of the network upgrade</strong></h2><p id="">‍</p><h3 id=""><strong id="">How will the upgrade from Olympia to Babylon happen?</strong></h3><p id="">A <a id="" href="https://learn.radixdlt.com/article/what-is-coordinated-protocol-update">protocol update</a> for the Olympia network will be released which defines a specific epoch as the last epoch of the Olympia protocol before the upgrade to the Babylon protocol with all of its new features.&nbsp; Assuming that this update is adopted by the Olympia validators, the countdown to Babylon will begin.</p><p id="">At the conclusion of the last Olympia epoch, all Olympia nodes will calculate and store the final network state of Olympia, and then stop participating in consensus.&nbsp; Babylon node software will use this final state as input for a new Babylon genesis, with all nodes agreeing on the correct start state that keeps everything where it was at the end of Olympia.&nbsp; As soon as validator nodes comprising over two thirds of delegated stake have ingested the genesis state and started processing transactions, the first epoch of Babylon will begin!</p><p id="">The total downtime for the switchover to occur is expected to be less than half an hour.</p><p id="">‍</p><h3 id=""><strong id="">What happens to all the existing tokens?</strong></h3><p id="">All existing tokens will be upgraded to become the new style of native <a id="" href="https://learn.radixdlt.com/article/what-are-native-assets">resources</a> on Babylon, and will be located in <a id="" href="https://learn.radixdlt.com/article/what-are-smart-accounts">smart accounts</a> controlled by the same keys that controlled their Olympia accounts.</p><p id="">The configuration of the new resource-based tokens will be set to mimic the behavior of those tokens on Olympia.&nbsp; Symbol, name, and description will be mapped to new metadata fields.&nbsp; Tokens which were set to have a mutable supply will have a badge created with the authority to mint and burn them, and that badge will be placed in a smart account controlled by the same key which had that authority on Olympia.&nbsp;</p><p id="">Other new resource behaviors not possible on Olympia will be locked off from the migrated assets, so that holders can be confident that nothing surprising can suddenly happen with their tokens that could not happen on Olympia.</p><p id="">‍</p><h3 id=""><strong id="">What happens to staked XRD?&nbsp; Do I need to restake?</strong></h3><p id=""><strong id="">There’s no need to restake, and you shouldn’t, as your stake helps maintain network security!</strong>&nbsp; Your stake positions will be unchanged, and you’ll automatically receive Liquid Stake Units to represent those positions in the appropriate smart accounts as part of the migration process.</p><p id=""><a id="" href="https://learn.radixdlt.com/article/how-will-staking-work-on-babylon">Staking works a little differently</a> on Babylon, and is achieved via interactions with native Validator components.&nbsp; All validators with any allocated stake will automatically have a Babylon Validator component created for them, with all staked XRD moved into it, the same signing key assigned, and the control badge placed in the smart account associated with the owner’s address.&nbsp; An appropriate quantity of Liquid Stake Units will be created for each validator, and placed in all their stakeholders' accounts.</p><p id="">‍</p><h3 id=""><strong id="">What happens to tokens held by various applications?</strong></h3><p id="">Remember that there are no smart contracts on Olympia…those applications which have sprung up are running off-network and simply hold tokens in normal accounts, which will be migrated like any others.&nbsp; Application builders, you may wish to consider communicating with your own user base about how your particular off-network application will migrate forward.</p><p id="">‍</p><h3 id=""><strong id="">What happens to network addresses?</strong></h3><p id="">Babylon addresses have a different scheme, so all Olympia addresses will need to be mapped to their Babylon equivalent.&nbsp; Wallet users will see their new account addresses automatically as part of their migration process, a web tool will be made available which can do the mapping, and devs/integrators will be able to use the <a id="" href="https://github.com/radixdlt/radix-engine-toolkit">Radix Engine Toolkit</a> to programmatically map addresses.</p><p id="">‍</p><h3 id=""><strong id="">Upgrading to the Radix Babylon Wallet</strong></h3><p id="">If your accounts are held in the <a id="" href="https://wallet.radixdlt.com/">Radix Olympia Desktop Wallet</a>, whether using it alone or with a <a id="" href="https://learn.radixdlt.com/article/using-ledger-nano-s-or-x-with-the-radix-desktop-wallet">Ledger hardware wallet</a>, migration will be a snap.&nbsp; With just a couple of clicks, the desktop wallet will pop up a QR code which you’ll scan with your Babylon mobile wallet, bringing across all of your known accounts and the names you assigned them.&nbsp; Then you’ll type in your seed phrase and you’re done.&nbsp; Ledger hardware device users will need to connect their Babylon mobile wallet to the Radix Connector browser extension, and then connect their Ledger device during the import process and follow some prompts.</p><p id="">If you use a wallet other than the Radix Olympia Desktop Wallet, it’s very likely that all you’ll need is your seed phrase in order to migrate successfully.&nbsp; Try entering your seed phrase into the Radix Olympia Wallet and see if you’re able to recover successfully and see your same accounts (remember, you may need to “Add Software Account” within the Wallet multiple times to see them all).&nbsp; If so, you’re all set.</p><p id="">A technical guide will be released ahead of Babylon explaining the QR code generation process, enabling third-party wallet providers to support the same no-hassle migration process, if they so choose.</p><p id="">To remove any user uncertainty, a step-by-step video guide for upgrading from the Radix Olympia Wallet will also be released.</p><p id="">‍</p><h2 id=""><strong id="">Network Upgrade Q&amp;A</strong></h2><p id="">‍</p><p id=""><strong id=""><em id="">So my automatically created smart accounts will forever be controlled by the same keys as I had on Olympia?</em></strong></p><p id="">Only if you want them to be.&nbsp; <a id="" href="https://learn.radixdlt.com/article/how-are-smart-accounts-created-controlled-and-recovered-on-babylon">Just like any smart account</a>, you’ll be able to easily “change the locks” whenever you want once multi-factor is implemented in the Radix Wallet.</p><p id="">‍</p><p id=""><strong id=""><em id="">What about exchanges and custom integrations that don’t use consumer wallets?&nbsp; How will they migrate?</em></strong></p><p id="">They’ll be able to map from either public keys or Olympia addresses to Babylon addresses, and use the Radix Engine Toolkit for basic transaction building while they acclimate to the Babylon transaction model, using their same keys for signing as before.&nbsp; Discussions with exchanges are underway to ensure they have everything they need to perform a smooth migration to the new accounts, and new style of transactions.</p><p id="">‍</p><p id=""><strong id=""><em id="">I don’t wish to use a mobile wallet.&nbsp; How will I be able to access my tokens on Babylon?</em></strong></p><p id="">There are no plans for an official desktop-native wallet.&nbsp; In short, with Babylon’s native multi-factor support and powerful account recovery model, mobile-only was the clear path forward.&nbsp; Don’t forget that you’ll be able to easily connect to your desktop browser using Radix Connect!</p><p id="">‍</p><p id=""><strong id=""><em id="">I use a Ledger hardware wallet on the Olympia network. How will the transition to Babylon work for me?</em></strong></p><p id="">Just as with all Olympia accounts, they will automatically migrate over - you don’t need to move your tokens or stakes and you will be able to use your Ledger with the same accounts on Babylon. There will be a new Radix app to load onto your Ledger device, and the process described above to access your accounts from the Babylon wallet will work with Ledger too.</p><p id="">‍</p><p id=""><strong id=""><em id="">Do I have to upgrade to the Babylon Wallet right away after the network update?</em></strong></p><p id="">Nope!&nbsp; Your stakes will still operate and earn emissions without any action on your part, and your tokens will all be migrated as part of the network upgrade without any action on your part.&nbsp; You can set up your Babylon mobile wallet whenever you’re ready; there’s no rush.</p><p id="">‍</p><p id=""><strong id=""><em id="">Will the Olympia network continue to run after the upgrade?</em></strong></p><p id="">No.&nbsp; All Olympia nodes will cease participating in consensus at the conclusion of the last epoch.&nbsp; Node-runners may choose to keep their Olympia nodes running, in which case they can still synchronize any new Olympia nodes joining the network, but no new transactions will be accepted or processed.</p><p id="">‍</p><p id=""><strong id=""><em id="">Will the Radix Olympia Wallet still function after the upgrade?</em></strong></p><p id="">Yes, though its only purpose at that point will be to let you smoothly export to the Babylon-compatible mobile wallets.&nbsp; It will not be able to initiate new transactions, and your account balances will always appear to be the same as they were at the conclusion of Olympia.</p><p id="">‍</p><p id=""><strong id=""><em id="">Will I still be able to see Olympia transaction history after the upgrade?</em></strong></p><p id="">Yes, existing explorers utilizing the Olympia Network Gateway can continue to operate, but that data will be forever frozen, and there are no plans to display Olympia and Babylon transactions in a single place.</p><p id="">The Radix Explorer present at <a id="" href="https://explorer.radixdlt.com">https://explorer.radixdlt.com</a> will continue to operate for at least 3 years, and will show the end state of Olympia.</p><p id="">The final Olympia state used to form Babylon genesis will <em id="">not</em> include the history of all transactions.&nbsp;Olympia transaction data will not be visible to Babylon nodes.</p><p id="">‍</p>
